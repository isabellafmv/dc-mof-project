# MOF CO2 Adsorption: Prediction and Interpretation

Machine-learning study predicting CO2 adsorption in metal-organic frameworks (MOFs)
from structural and chemical descriptors, on the hypothetical-MOF (hMOF) dataset.
Three model families (XGBoost, Random Forest, and a multilayer perceptron) are compared
across 7 feature sets and 3 data-split strategies, then interpreted with SHAP and probed
for the structures that all models consistently mispredict.

The single regression target throughout is CO2 uptake at 0.1 bar (mol/kg).

## Data

Only code is included in this submission. The `data/`, `models/` and `results/`
directories are not shipped: the datasets are large and the models and results are
regenerated by running the notebooks below.

### Source

The dataset is the hypothetical-MOF (hMOF) collection from MOFDB
(https://mof.tech.northwestern.edu), accessed programmatically with the `mofdb_client`
package rather than by manual download. `notebooks/01_dataset_exploration.ipynb` fetches
every hMOF record via `fetch(database="hMOF")` (resumable, checkpointed):

- geometric descriptors (PLD, LCD, surface area, void fraction, density),
- CO2 isotherm uptakes (0.01-2.5 bar), and
- metadata (topology, metal node, MOFid / MOFkey, mofdb_id).

The per-MOF crystal structures (`data/cif_structures/<name>.cif`, used only for RACS
feature generation) come from the same MOFDB records.

### Reproducing the data

Install the client and run the data-preparation notebooks (steps 1-4 in the Pipeline):

```bash
pip install mofdb-client
```

`01_dataset_exploration.ipynb` writes the raw and cleaned tables
(`data/raw/hmof_dataset.parquet`, `data/cleaned/hmof_dataset_cleaned.parquet`); the rest
of `data/` (RAC features, merged dataset, splits) is produced by the later prep steps.

## Pipeline

Each stage writes files consumed by the next.
The modelling notebooks skip experiments whose output files already exist, so partial
reruns are cheap.

Pipeline ownership: XGBoost (Isabella), Random Forest (Alina), and MLP (Hannah). Each member owns that model's training, SHAP, and outlier notebooks.

For the general workflow it is important that one of the group members was in charge of one model pipeline, this is also why there are seperate outlier analysis and shap notebooks, even though the style across these is roughly the same. 

To ensure consistency, notebooks were often adjusted to match styles overall and pipelines were always discussed before individual implementation.

**Data preparation**

1. `notebooks/01_dataset_exploration.ipynb`: explore and clean the raw data
   -> `data/cleaned/hmof_dataset_cleaned.parquet`
2. `notebooks/02_mofdscribe_racs.ipynb`: RACS chemical descriptors from the CIFs
   -> `rac_features.parquet`
3. `notebooks/03_correlation_analysis.ipynb`: merge geometric + RAC features, apply variance
   and correlation filtering, and define the 7 feature sets
   -> `data/merged/hmof_merged.parquet`, `data/merged/feature_selection.json`
4. `notebooks/04_data_splits.ipynb`: build the 3 split strategies (random / topology / metal)
   -> `data/splits/split_{strategy}_{train,test}_merged.parquet`
5. `notebooks/05_rac_completeness_analysis.ipynb`: quantify the linker-RAC computation
   failure and check it for systematic bias (QA on the RAC features)
   -> `results/rac-completeness/`

The 7 feature sets (defined in `feature_selection.json`, loaded via `src/data_utils.py`):
`baseline` (2 encoded categoricals), `geo_decorr` (5), `geo_all` (6), `rac_decorr` (45),
`rac_all` (81), `combined_decorr` (50), `combined_all` (87).

**Model training** (7 feature sets x 3 splits = 21 experiments per model)

6. `notebooks/06_xgboost_training.ipynb` -> `models/xgb/`, `results/xgb/`
7. `notebooks/07_random_forest_training.ipynb` -> `models/rf/`, `results/rf/`
8. `notebooks/08_mlp_training.ipynb` (fixed architecture) + `scripts/run_hpo_geo_rac.py` (HPO)
   -> `models/mlp/`, `results/mlp/mlp_summary.csv`

**SHAP interpretation** (18 non-baseline experiments per model)

9.  `notebooks/09_xgboost_shap.ipynb` -> `results/xgb/shap/`
10. `notebooks/10_random_forest_shap.ipynb` -> `results/rf/shap/`
11. `notebooks/11_mlp_shap.ipynb` -> `results/mlp/shap/`

**Outlier analysis** (MOFs mispredicted across the 9 conditions per model)

12. `notebooks/12_xgboost_outliers.ipynb`
13. `notebooks/13_random_forest_outliers.ipynb`
14. `notebooks/14_mlp_outliers.ipynb`
    -> `results/prediction-outlier-analysis*/outlier_predictions_*.parquet` + plots

**Cross-model comparison** (needs the per-model summaries, SHAP caches and outlier parquets)

15. `notebooks/15_model_comparison.ipynb`: test R²/RMSE/MAE across all models -> `results/comparison/`
16. `notebooks/16_outlier_comparison.ipynb` -> `results/model-comparison-outliers/`
17. `notebooks/17_shap_comparison_poster.ipynb` -> `results/model-comparison-outliers/poster/`

## Shared loader

All model notebooks pull data through
`src.data_utils.load_experiment(split_strategy, feature_set)`, which returns
`X_train, X_test, y_train, y_test` as numpy arrays from `hmof_merged.parquet` using the
named feature sets and split membership. This keeps the feature definitions identical
across XGBoost, Random Forest and the MLP, so their results are directly comparable.
